Wearable collision anticipation

Two teachers, and the student that copies one of them

All three networks look at the same kind of clip: 16 RGB frames covering the last 3 seconds, and they score danger on a 5×5 grid. They are three systems. The root notes describe a teacher that emits four maps. A separate note describes the one-second parent that the student copies. The student is a small network with no giant video encoder.

Overview

The job is anticipation for a wearable camera. At an anchor time t, the network may see only the past, including the frame at t. It fills a 5×5 danger map whose cells run from 0 (safe) to 1 (maximum threat). It does not output a collision-versus-miss class, and it does not take a background id as an input switch.

CollisionTeacher3 is the model in README.md, MODEL_DATAFLOW.txt, FILE_GUIDE.txt, and PREPROCESSING_PIPELINE.txt. It keeps a frozen V-JEPA 2 Giant encoder, trains a small adapter and four heatmap heads, and can later add LoRA on the last six Giant blocks.

The Pair-CF parent is the model in docs/parent_pair_cf_model.md. It also uses a frozen Giant, and it trains an adapter plus one heatmap decoder. The treatment adds a counterfactual shrink on Giant tokens. That file is the parent the student is allowed to copy. Checkpoint model_trial_3/checkpoints/pair_cf_treatment_s1337/teacher_phase_a_best.pt, seed 1337, decoder hash 77f78c8714667617.

Student M1 is the model in docs/student_m1_model.md. It learns a small (2+1)D encoder so that its feature map sits near the parent’s F_dec, then runs the copied decoder. Seed 1001. Official checkpoint model_trial_3_temp/overnight6/m1_stop_floor/checkpoint_epoch_10.pt.

Where the notes use different words.
  • README.md, MODEL_DATAFLOW.txt, FILE_GUIDE.txt, and PREPROCESSING_PIPELINE.txt say heatmap row 0 is far / top and row 4 is near / feet. docs/parent_pair_cf_model.md says “Rows are depth (near→far)” and does not assign row 0 or row 4. Columns agree in every file: left is columns 0–1, center is column 2, right is columns 3–4.
  • README.md’s change list says a pre-fork history with a split future is masked. The pairing section of that same file, and FILE_GUIDE.txt, say the live default is mean_target: both clips train on the cell-wise average. FILE_GUIDE.txt says to trust that guide when it and the README disagree. mask_ambiguous_pairs is a different setting, and that one skips the horizon.
  • FILE_GUIDE.txt describes the dummy test encoder’s default crop as 64×64 (4×4 spatial tokens). MODEL_DATAFLOW.txt says build_backbone(dummy=True) uses input size 256, so that factory path has 16×16 spatial tokens and shape [B, 2048, 64]. Hidden size 64 is in both notes. The dummy path is for tests and smoke runs.

Shared input

Every system’s clip is 16 frames ending at anchor t. The same letterbox and the same 5×5 label grid are the common contract. Which anchors get drawn is a separate schedule for each note.

Sixteen frames, three seconds

Letterbox and the 5×5 grid

  1. Pixels after the letterbox Float32 in the range 0 to 1. One clip is [16, 3, 256, 256]. A batch is [B, 16, 3, 256, 256]. The dataset tensor is still un-normalized. Black pad is 0 in that tensor. Heatmaps are already 5×5, one per frame, values in 0 to 1. They are not resized to 256.
  2. ImageNet numbers, inside the teachers’ Giant PREPROCESSING_PIPELINE.txt and MODEL_DATAFLOW.txt print mean (0.485, 0.456, 0.406) and standard deviation (0.229, 0.224, 0.225). A black pad pixel then sits near −2.12, −2.04, −1.80 on red, green, and blue. The parent note and the student note both say ImageNet normalization and do not reprint those six numbers.
  3. Geometry that stays off Flips, rotation, scale jitter, color jitter, and blur are off, because left and right are part of the label. Source clips in the root notes are 1920×1080, 30 fps, 450 frames (15 seconds). A legal anchor needs 3 seconds of history, so t starts at 90. The scenario fork is frame 365 (12.15 seconds): before that frame, collision and miss footage of the same sample still match.
  4. Worked anchor, t = 330 The 16 input frames are 240, 246, 252, 258, 264, 270, 276, 282, 288, 294, 300, 306, 312, 318, 324, 330. In the four-map notes the label times are now = 330, 1 s = 360, 1.5 s = 375, 2 s = 390. Those later times pick heatmap labels. They do not pull extra RGB.

What is shared, and what is scheduled differently

  1. Four-map anchors The loader walks t = 90, 105, …, 405 when partial horizons are allowed (about 22 anchors per clip, stride 15). Anchors with partial horizons allowed run t in the range 90 to 419, and the stride-15 list ends at 405.

Four-map teacher

CollisionTeacher3. Sources: README.md, MODEL_DATAFLOW.txt, FILE_GUIDE.txt, PREPROCESSING_PIPELINE.txt.

This teacher answers four questions on the 5×5 grid: danger now, 1.0 s later, 1.5 s later, and 2.0 s later. It also emits Z_t [B, 32, 5, 5], a 32-dimensional vector on each cell. The root README says there is no JEPA latent-matching loss in this teacher-only run. The student is out of scope in those root notes.

Forward path

  • Now, row 4 col 20.40
  • 1 s delta +0.350.75
  • 2 s delta +0.550.95

Illustration in MODEL_DATAFLOW.txt, not a measured clip. The 1.5 s map is not part of this walk-through. If a delta is about 0, that future map copies the now map.

Backbone, adapter, heads

  1. Giant contract Preferred weights are V-JEPA 2 Giant, hidden size 1408. README.md names Large (facebook/vjepa2-vitl-fpc64-256) as the fallback if Giant cannot load, and says a run must not claim Giant when the fallback was used. The encoder call is get_vision_features, or the model forward with the V-JEPA predictor skipped. Tokens are cast to float32 and must be exactly [B, 2048, 1408]. The code refuses to drop or pad tokens.
  2. Frozen phase, then optional LoRA train() forces the backbone to eval, so dropout and batch-norm inside Giant stay in eval while the adapter and heads train. In the frozen phase the Giant forward runs under no_grad and the base weights have requires_grad false. Full Giant weights are not stored in the project checkpoint. The Hugging Face id is recorded and loaded again.
  3. Spatial projection, shared across time Tokens reshape to [B, 8, 16, 16, 1408] and move to [B, 8, 1408, 16, 16]. Each time group uses the same weights: a 1×1 convolution 1408 to 128, GELU, then a 3×3 convolution 128 to 128, GELU. Space stays 16×16. The projected tensor is [B, 8, 128, 16, 16].
  4. Two temporal residual blocks Kernel 3, dilation 1. One block is a depthwise time convolution, kernel (3, 1, 1), padding (1, 0, 0), groups 128, then a pointwise 1×1×1 convolution, GroupNorm with 8 groups, GELU, and a residual add. Space is still 16×16. The tensor is then [B, 128, 8, 16, 16].
  5. Mean and last Mean over the 8 groups gives [B, 128, 16, 16]. The last group alone gives [B, 128, 16, 16]. Concatenate to [B, 256, 16, 16]. A 1×1 and GELU return [B, 128, 16, 16]. The notes call this mix mean_last.
  6. Pool down to Z_t Adaptive average pooling makes the grid 5×5, giving [B, 128, 5, 5]. A 1×1 convolution 128 to 128 with GELU, a 1×1 convolution 128 to 32, and a LayerNorm over the 32 channels of each cell produce Z_t [B, 32, 5, 5]. In these root notes, row 0 of that 5×5 is the top / far part of the letterboxed image and row 4 is the bottom / near / feet.
  7. Now decoder Hhat_now = sigmoid of the decoder on Z_t, in the open range 0 to 1. The decoder is 32 to 48 (1×1, ReLU), 48 to 48 (3×3, ReLU), 48 to 1 (1×1).
  8. Future residual, then a stopped add For each horizon, Zhat = Z_t + f(Z_t). The predictor f is 32 to 96 (3×3, ReLU), 96 to 96 (3×3, dilation 2, ReLU), 96 to 32 (1×1). The delta is tanh of g(Zhat − Z_t), in the open range −1 to 1. The delta head g is 32 to 48 (1×1, ReLU), 48 to 48 (3×3, ReLU), 48 to 1 (1×1). The future map clamps (stopped now map + delta) into 0 to 1. Horizons are named 1s, 1_5s, and 2s.

The forward ignores the label maps, the ambiguity flags, outcome and background strings, and the pairing ids. Two clips with the same RGB therefore produce almost the same maps. Outcome differences enter through the targets.

Labels, fork, and masks

  1. Which horizons must exist Default batch size in the root config is 1. The 1 s label must exist. A 1.5 s or 2 s label past frame 449 is masked and skipped. Requiring all three futures narrows the range to t in 90 to 389, last stride-15 anchor 375.
  2. Live policy, mean_target FILE_GUIDE.txt, and the pairing section of README.md, train both the collision clip and the miss clip on the cell-wise average when t is still before the fork and a future heatmap has already split. The now-map loss is kept. At the guide’s example t = 330, the 1 s frame 360 is still shared, while 375 and 390 have split. A cell that is about 0.96 on the collision map and about 0 on the miss map becomes 0.48 in the rewritten target. After the rewrite those horizons are trained, and the ambiguity flag for them is cleared.
  3. The other switch mask_ambiguous_pairs skips a split horizon instead. README.md’s short change list also describes that masking behavior. FILE_GUIDE.txt says to follow the guide when the two descriptions disagree.
  4. Background pairs bg_00 and bg_01 share the threat and change clutter and lighting. When the heatmaps agree within tolerance 0.001, a cosine term pulls the two Z_t tensors together. The pair buffer stores one detached Z_t at a time (maximum 64 entries) so both Giant graphs are not held together. Outcome disagreement uses tolerance 0.02 on the maximum absolute cell difference. Splits are by sample group, 0.70 / 0.15 / 0.15, so a collision clip and its miss mate stay in the same split. Config seed is 1337.

Training schedule

Phase A
8 epochs. AdamW on the adapter, the now decoder, the three predictors, and the three delta heads. Learning rate 1e-3. Giant frozen.
Phase B
10 epochs. LoRA on every linear layer in the last 6 Giant blocks. Rank 16, alpha 16, so alpha/rank = 1. Adapter and heads at 2e-4. LoRA at 1e-4. Base Giant weights stay frozen.
LoRA step
Output = base weight times the input, plus (alpha / rank) times B applied to (A applied to the input). A is kaiming-uniform, B starts at zero, dropout 0, so the output is unchanged at the moment LoRA is turned on.
Schedule
One epoch of linear warmup, then cosine down to 1e-6. Gradient clip 1.0. Micro-batch 1. AMP bfloat16 when the GPU supports it. Patience 4 evaluations.
Best checkpoint
Weighted high-threat recall on the three futures, plus STOP F1. Eligible only if nuisance ≤ 0.20 and miss ≤ 0.25. High-threat cells use threshold 0.5. Selection is not raw MSE.
Files
checkpoints/teacher_phase_a_last.pt, teacher_phase_a_best.pt, teacher_phase_b_last.pt, teacher_phase_b_best.pt.

Nuisance, in the evaluation notes, is a CAUTION-or-STOP prediction on a SAFE frame. Miss is a SAFE prediction on a STOP frame. The warning rule for this teacher is separate from the parent’s rule: after a row-weighted peak over left, center, and right, peak ≥ 0.70 is STOP, peak ≥ 0.42 is CAUTION, and anything lower is SAFE.

The loss line is below, in Losses. There is no 1 s-only BCE and no pair-difference PCA in this teacher.

Test encoder. FILE_GUIDE.txt describes DummyVJEPA2Backbone with a default 64×64 crop, hidden size 64, 8 time groups, and 4×4 spatial tokens. MODEL_DATAFLOW.txt says the factory build_backbone(dummy=True) uses input size 256, so the usual dummy tokens are [B, 2048, 64], and a hand-built 64 crop is the 4×4 case. Tests use the dummy and do not download Giant.

One-second teacher

Pair-CF parent. Source: docs/parent_pair_cf_model.md. This is the teacher the student copies.

The input contract is the same 16 letterboxed frames. The output is one map, Hhat_1s [B, 5, 5], occupancy one second after t (frame t+30). The mode is direct_h1s: the decoder output is that 1 s map. There is no now head, no 1.5 s head, no 2 s head, and no copy-residual delta. Giant stays frozen for the whole treatment. The phase flag is frozen. This treatment does not turn on LoRA.

Forward path

  1. Cache, eval, and the skipped predictor The parent note says tokens are typically cached. The backbone stays in eval during training. AMP runs in bfloat16. skip_predictor is true: V-JEPA’s own future-token predictor is not the training loss.
  2. Four blocks, kernel left to the other note After the spatial projection, four temporal residual blocks use dilations 1, 2, 1, 2. The note describes each block as a depthwise time convolution, a pointwise mix, GroupNorm, and GELU. It does not restate the kernel size. The four-map dataflow, for its own two blocks, does: kernel 3 along time and GroupNorm with 8 groups.
  3. Softmax pool, with a recency bias The parent note names the pool and does not write the expression. The implementation in collision_jepa3/models/spatial_adapter.py is a per-location softmax over the time groups. The hidden width is the greater of 8 and the channel count divided by 4 with integer division. At 128 channels that is 32. Two 1×1×1 convolutions score each place: channels to hidden, GELU, hidden to 1. Add a learned recency value, one per time group, initialized as a line from −1 to 1 so later tubelets start higher. Softmax over time, then a weighted sum of the groups, gives [B, 128, 16, 16]. That map is F_dec (also called fine). The parent note does not add a last-frame gate on top of this pool.
  4. Optional knobs the note mentions The map can optionally be resized to heatmap_grid 16. An optional drop of 16 channels can sit on fine before the decoder. The note’s wording is that this drop can sit there, and that the pair-CF path still reads that stream.
  5. Decoder the student copies 1×1, 128 to 48, ReLU. 3×3, 48 to 48, ReLU. 3×3, 48 to 48, dilation 2, ReLU. 1×1, 48 to 1 logit, still 16×16. Adaptive max-pool to 5×5. Sigmoid to Hhat_1s. No batch-norm. Sigmoid after the max-pool matches a max of sigmoids, so the pooled 5×5 logits are valid for BCE-with-logits. Counting those four convolutions with one bias each gives 6,192 + 20,784 + 20,784 + 49 = 47,809 parameters. Hash in the best Pair-CF checkpoint: 77f78c8714667617.
  6. Where Z_t is used The four-map dataflow spells its own bottleneck as 128 to 128 and then 128 to 32. The parent note summarizes its bottleneck as 128 to 32 plus LayerNorm. The diagram in the parent file also tags Z_t with “pair-CF”. The pair-difference shrink itself is applied to Giant tokens. The background term is the cosine on Z_t.
  7. Warning and labels SAFE if the peak is below 0.25, THREAT if the peak is at least 0.25 and below 0.60, STOP if the peak is at least 0.60. These cuts are the parent’s and the student’s. They are a different rule from the four-map teacher’s 0.70 / 0.42 bands. On labels, when background-pair futures disagree, targets use the cell-wise mean of collision and miss (ambiguous_policy: mean_target), and ambiguous 1 s maps can be masked (amb_1s). The fork remains frame 365.

Pair-difference shrink

  1. What was fit Each window’s Giant tokens, T = 2048 and C = 1408, are averaged over tokens to a clip vector in a 1408-dimensional space. For a pair (a, b) at the same anchor, D is one-half of (vector a − vector b). Subtract the mean of D, then PCA. Values k = 4, 8, and 16 were fit. This treatment uses k = 16. U has shape 16 × 1408, and U times its transpose is about the 16×16 identity. The note’s intent is that these directions are mostly nuisance (lighting and background identity), and that occupancy should remain in the orthogonal complement.
  2. How a training step applies it A paired batch is the first half clip A and the second half clip B. Token tensors are [B/2, T, C]. The same half-difference is formed from the token means, projected, and applied with scale = 1. The channel vector d equals (D times U transpose) times U, broadcast over tokens. Shrunk A is A − d. Shrunk B is B + d. The same d hits every token position. The shrunk tokens go through the adapter and the decoder, and TeacherLoss is computed again on the same labels. That copy’s background term is 0. The clean path is left as it is. The loss section lists the weights.
  3. What “halves” refers to The same note says this halves the pair-difference inside the span of U. D already contains the one-half, and d is subtracted from A and added to B, so the subspace piece of the full mean difference is cancelled. The orthogonal complement is unchanged.
  4. When it runs On a batch whose bg_reg_paired flag is true. The whole batch is kept or dropped together: the first byte of the SHA-256 of epoch|background_pair_id[0]|pair_cf_aux must be below 128. pair_cf_pair_frac is 0.5 in configs/default.yaml, the launch script passes the same 0.5, and round(0.5 × 256) is 128. pair_cf_ramp_strength is 0 at epoch 0, 0.25 at epoch 1, 0.50 at epoch 2, 0.75 at epoch 3, and 1.0 from epoch 4 on. docs/parent_pair_cf_model.md lists those levels and does not name the later epochs. Beta is set once at the start of epoch 1. The loss section writes that calibration.

Student

Student M1, variant m1_stop_floor. Source: docs/student_m1_model.md.

M1 is the small RGB student. It does not run V-JEPA. It maps the 16 frames onto a parent-shaped feature, then uses the copied Pair-CF decoder. The predictor inside M1 exists for a masked reconstruction term. The heatmap path does not go through that predictor.

Student flow beside the parent

Encoder steps

  1. Layout for the 3D convolutions ImageNet normalization, then a permute from [B, 16, 3, 256, 256] to [B, 3, 16, 256, 256].
  2. Stem 3 to 64 channels. Kernel and stride (2, 16, 16). On 16 frames of 256×256 that makes 8 time steps and a 16×16 grid, with 64 channels.
  3. Stack written in the student note Two inverted residuals at width 64, expand 4. A 1×1 projection to 128 channels. Six inverted residuals, expand 3, time dilations 1, 2, 1, 2, 1, 2. One extra inverted residual, expand 2. student_model/encoder.py builds this extra block, and the two width-64 blocks, with time dilation 1. Softmax pool over the time axis, plus a learned last-frame gate, producing F_ctx [B, 128, 16, 16].
  4. One inverted residual Width C, expand e, time dilation d, middle width C times e. GroupNorm uses 8 groups. Apply GELU to a pointwise expand from C to C·e. Depthwise convolution, kernel (1, 3, 3). Depthwise convolution, kernel (3, 1, 1), dilation d. Pointwise project from C·e back to C. GroupNorm. Output is GELU of (input + that result). The two depthwise convolutions sit between the two GELUs with no extra nonlinearity of their own.
  5. Last-frame gate, then the 1×1 The pool module is the same softmax written for the parent. The encoder then adds a gate the parent note does not use. g is one learned scalar, initialized at 0, and the newest time step is added as g times that step: F_ctx = softmax pool + g × newest step. A 1×1 maps F_ctx to F, both [B, 128, 16, 16]. Its weight is initialized to the 128×128 identity, so early in training F matches F_ctx. F is what the decoder sees, and what the latent losses compare with cached parent F_dec. The projection has 16,512 parameters.
  6. Predictor, masked cells only JEPAPredictor is a small masked CNN on F_ctx only. The student note describes an identity skip, a depthwise residual, and a 1×1 that starts at zero, so the predictor starts as the identity. A 2D sine-cosine position embedding is added inside the residual. A Bernoulli mask with probability 0.5 drops cells on the 16×16 grid (cells, not tubelets). The masked input is the mask times (F_ctx + position). The prediction is F_ctx plus a 1×1 of a depthwise block on that masked input. Visible cells still pass through the F_ctx skip. Masked cells have to be filled by the predictor. This is the student note’s own predictor. It is not V-JEPA’s predictor, and it is not the pair-CF shrink. M1 has no 3-way auxiliary classifier and no second branch on the most recent four frames. Those belong to other variants.
  7. What the loss reads Decoder logits exist. The M1 loss uses probabilities Hhat_1s, not those logits. Peak class uses the parent cuts: SAFE below 0.25, THREAT below 0.60, otherwise STOP.

Total loss

=
future loss future loss = 0.50 × (1 second map) + 0.30 × (1.5 second map) + 0.20 × (2 second map) Compares each future map with its label. A high value means a future map is wrong.
+
0.25 × now-map loss Compares the now map with the now label. A high value means the now map is wrong.
+
0.20 × delta loss Compares the predicted change with the gap from the stopped now map to the future label. A high value means that change is wrong.
+
0.10 × false-positive loss Looks at cells the label calls empty. A high value means the prediction painted danger above 0.10.
+
0.05 × direction loss Compares the predicted side with the labeled side when the label peak is above 0.42. A high value means the side is wrong.
+
0.02 × background loss Compares the two Z_t vectors on backgrounds that share a threat. A high value means those vectors point apart.

FILE_GUIDE.txt adds a detail the one-line form compresses. For each future horizon the map term, the delta term, the false-positive term, and the direction term are computed under that horizon’s mask, then multiplied by 0.50, 0.30, or 0.20. The now term is outside those horizon weights, and it is never dropped by the ambiguity mask. A horizon whose mask is on is skipped. Under mean_target, a rewritten future has its mask cleared, so it is trained on the averaged map. If a whole batch is masked, the weighted map term returns 0.

Map loss inside the now map and each future map

0.25 × now

Called L_now, L_1s, L_1.5s, and L_2s. Inside the future loss the same map rule is scaled by 0.50, 0.30, and 0.20.

  • Weighted mean squared error of (prediction − target).
  • Cell weight = 0.05 + 4 × (target value)², then divided by the mean of those cell weights.
  • Row weights from top to bottom: 0.8, 0.9, 1.0, 1.1, 1.2, normalized so the mean is 1.

This compares a predicted danger value with the target value. A high value means the cell is wrong, with a harder pull where the target is already dangerous and on nearer rows. Weights come from the target map, so predicting zeros does not hide a cell.

Delta loss

0.20 ×

Called L_Δ. Mix coefficient delta_residual_mix = 0.5. Each future horizon’s copy is also scaled by 0.50, 0.30, or 0.20.

  • Target change = future label minus the stopped now prediction, then clamped into −1 to 1.
  • Compare the predicted delta with that target using the same weighted squared error.
  • Mix in an extra penalty on the size of the residual. The guide names the 0.5 mix and does not expand it into a second line.

This compares the horizon’s delta with how the future label differs from the stopped now map. A high value means that change does not match.

False-positive loss

0.10 ×

Called L_FP. Each future horizon’s copy is also scaled by 0.50, 0.30, or 0.20.

  • On cells whose target is below 0.05, square how far the prediction sits above 0.10.
  • A prediction at or below 0.10 adds nothing on that cell.

This compares an almost-empty target cell with the prediction. A high value means danger was painted on a cell the label calls empty, once the prediction rises above 0.10.

Direction loss

0.05 ×

Called L_dir. The root notes name a temperature and do not print its value. Same per-horizon scales as the map term.

  • A side score is the temperature times the log-sum-exp of (row-weighted cells divided by that temperature).
  • Softmax over left (columns 0–1), center (column 2), and right (columns 3–4).
  • Cross-entropy against the ground-truth side, only when the ground-truth peak is above 0.42.

This compares the predicted side of the scene with the labeled side. A high value means the mass is on the wrong side, even if the exact cells are a little off. Windows whose target peak is 0.42 or below stay out.

Background loss

0.02 ×

Called L_bg. Zero when no mate is in the pair buffer.

  • Over the 25 cells, average (1 − cosine of the two 32-d vectors).

This compares Z_t on two backgrounds whose heatmaps agree. A high value means the same threat landed far apart. An empty buffer contributes 0.

One-second teacher

Pair-CF treatment, seed 1337, heads.mode direct_h1s. Sum: TeacherLoss.__call__ in collision_jepa3/losses/composite.py. Counterfactual add and buffer cosine: PhaseTrainer._forward_loss in collision_jepa3/training/trainer.py. scripts/04_train_teacher.py loads configs/default.yaml, then submit_pair_cf_treatment_s1337.sh writes the overrides named below.

The map term is BCE-with-logits on the pooled 5×5 logits Hhat_1s_logits. HeatmapDecoder.forward_with_logits max-pools the 16×16 decoder logits to 5×5 because adapter.heatmap_pool is max. Hinges, false positives, direction, and the close head use probabilities Hhat_1s or Hhat_close. The sample mask is true where amb_1s is false. That mask enters the cell weights, the blob keep-mask, both hinges, the false-positive cells, the direction samples, and the close head.

Taken from the yaml, with no launch override: blob weight 0.35 (loss.blob_bce_weight), false-positive weight 0.10, direction weight 0.05, background weight 0.02, appear multiplier 8, occupied-cell weight 2 when the label is above 0.1, disappear multiplier 1.0 (skipped by the code), shrink scale pair_cf_lambda 1.0, pair_cf_pair_frac 0.5, and pair_cf_grad_scale 0.10. The launch script sets STOP hinge weight 1.0, SAFE hinge weight 0.5, close weight 1.0, and the small-blob multiplier 2.0. The yaml defaults of those four are 0, 0, 0, and 1. A small-blob multiplier of 1 makes _small_blob_w add no extra factor. The launch script also passes pair fraction 0.5 and grad scale 0.10, the same numbers as the yaml.

Training total

=
1 × cell BCE Compares each pooled 5×5 logit with the 1 second label h_1s. A high value means a cell logit is wrong, with extra pull on appear cells and on a small STOP blob.
+
0.35 × blob loss Compares a 3×3 max of those logits with a 3×3 max of the label, on neighborhoods whose pooled label is at least 0.5. A high value means the true cell and its neighbors stayed low.
+
1.0 × STOP hinge On unmasked windows whose label peak is at least 0.60, penalizes how far the predicted peak sits below 0.65. A high value means that peak stayed below 0.65.
+
0.5 × SAFE hinge On unmasked windows whose label peak is below 0.25, penalizes how far the predicted peak sits above 0.25. A high value means a safe window was scored too hot.
+
1.0 × close loss Compares the sigmoid of a 1×1 on Z_t with the approaching map at the anchor plus 30 frames. A high value means that side head missed on an occupied auxiliary cell.
+
0.10 × false-positive loss On label cells below 0.05, squares how far the probability sits above 0.10. A high value means an empty cell was too hot.
+
0.05 × direction loss Compares soft left, center, and right scores of the probability map with the label, when the label’s largest side score is at least 0.25. A high value means the side profile disagrees.
+
0.02 × background loss Compares Z_t with a detached earlier mate on the clean forward. A high value means those 32-d cell directions differ. The term is 0 when the buffer has no mate, and the shrunk-token copy does not add it.
+
beta × ramp × the same TeacherLoss sum on shrunk tokens That copy is the cell, blob, STOP, SAFE, close, false-positive, and direction terms after apply_pair_counterfactual_shrink with scale 1.0. Its own background term is 0. Ramp is 0, 0.25, 0.50, 0.75, 1.0 at epochs 0, 1, 2, 3, and 4 onward. At full ramp, beta is set so this extra gradient is about 10% of the clean adapter-and-decoder gradient. Repeats the occupancy sum after the loaded pair-difference subspace is shrunk out of the Giant tokens. A high value means the 1 second map is hard to explain from the remaining channels.

TeacherLoss stores the hinges as L_stop_hinge and L_safe_hinge, from stop_peak_hinge and safe_peak_hinge, because loss.logit_hinges stays false. docs/parent_pair_cf_model.md calls them L_stop and L_safe.

soft_bce_logits divides by the weight sum after lifting that sum to at least 1e-6, and returns 0 when the sample mask is empty. The note writes the denominator as the weight sum plus epsilon.

The note places the background cosine inside L_task and copies that whole sum onto the shrunk tokens. TeacherLoss.__call__ sets L_bg to 0 because z_bg_pair is not passed, and _forward_loss never passes it. _bg_pair_tensor adds the buffer cosine on the clean forward after the counterfactual term.

The note says the mate is used when the 1 second maps agree. background_pair_valid in collision_jepa3/data/pairing.py requires every in-range horizon map (1 s, 1.5 s, and 2 s) to have maximum cell absolute difference at most sampling.background_target_tolerance, which is 0.001 in the yaml, and the two clips must share outcome, scenario group, and background pair id.

The note lists the ramp as off, then 0.25, 0.50, 0.75, then 1.0, and leaves the later epochs unnamed. pair_cf_ramp_strength in collision_jepa3/training/bg_regularization.py sets epoch 0 to 0, epoch 1 to 0.25, epoch 2 to 0.50, epoch 3 to 0.75, and epoch 4 onward to 1.0.

The note writes beta as 0.10 divided by the median of the counterfactual gradient size over the clean gradient size. calibrate_beta_pair_counterfactual divides pair_cf_grad_scale 0.10 by the median of g_cf / (g_clean + 1e-8). Each g is the L2 norm of adapter and heatmap-decoder gradients from adapter_trainable_grad_norm. Batches with g_clean at or below 1e-8 are skipped. With no ratios left, beta is 0.10.

Weights left at 0 in the yaml, so those terms add 0: beta_nll_weight, evidential_weight, prob_stop_weight, prob_safe_weight, and var_weight. direct_h1s builds the 1 s map, the close head, and the evidence head. The launch command leaves clean-anchor dropout, targeted dropout, random dropout, and pair-consistency off, so there is no L_drop and no L_bg_pair. TeacherLoss has no VICReg term.

Cell BCE

1 ×

Called L_1s. Function soft_bce_logits. Weight 1 is hardcoded in TeacherLoss.

  • BCE-with-logits between Hhat_1s_logits [B, 5, 5] and h_1s, clamped into 0 to 1.
  • Cell weight = (2 if h_1s is above 0.1, else 1) × appear weight × small-blob weight × sample mask. The 2 and the 0.1 are yaml bce_pos_weight and bce_pos_threshold.
  • Appear weight, from appear_cell_weight, is 8 when the now label h_now is below 0.1 and h_1s is at least 0.5, else 1. The 8 is yaml bce_appear_weight. The batch always carries h_now.
  • Small-blob weight, from small_blob_cell_weight, is 2 on cells with h_1s at least 0.5 when the peak of h_1s is at least 0.60 and the count of those cells is 1, 2, 3, or 4. The 2.0 is the launch flag --small-blob-weight. Other cells stay at 1. small_blob_max_cells is 4 in the yaml.
  • The term is the sum of (weight × BCE), divided by the weight sum after that sum is lifted to at least 1e-6. An empty sample mask returns 0.
  • Yaml bce_disappear_weight is 1.0, so _disappear_w adds no extra factor. The sample mask is true when amb_1s is false.

This compares each pooled logit with the 1 second label. A high value means the logit is wrong, with extra pull where the now label is below 0.1 and the future label is at least 0.5, and on a small STOP blob.

Blob loss

0.35 ×

Called L_blob. Function blob_bce_logits. The 0.35 is yaml loss.blob_bce_weight.

  • 3×3 max-pool, stride 1, pad 1 (maxpool3x3), on Hhat_1s_logits and on h_1s.
  • Keep neighborhoods whose pooled label is at least 0.5 (blob_occupied_threshold) and whose sample mask is true.
  • Mean BCE-with-logits on those kept cells. An empty keep-mask returns 0.

This compares a neighborhood of the pooled logits with the neighborhood of the label. A high value means neither the true cell nor a neighbor scored high. Empty neighborhoods stay out of the mean.

STOP hinge

1.0 ×

Stored as L_stop_hinge. Function stop_peak_hinge, called from TeacherLoss._stop_hinge. The 1.0 is the launch flag --stop-hinge-weight. The yaml default 0 would make _stop_hinge return 0.

  • Peaks are the max of Hhat_1s and the max of h_1s over the 5×5.
  • Keep windows whose label peak is at least 0.60 (loss.stop_hinge_threshold) and whose sample mask is true.
  • The target peak is 0.65. stop_hinge_target is null in the yaml, so the code uses threshold 0.60 plus stop_hinge_margin 0.05.
  • The term is the mean of relu(0.65 − predicted peak) on those windows. An empty set returns 0.

This compares the predicted probability peak with 0.65 on unmasked STOP windows. A high value means that peak stayed below 0.65. Windows whose label peak is below 0.60 stay out.

SAFE hinge

0.5 ×

Stored as L_safe_hinge. Function safe_peak_hinge, called from TeacherLoss._safe_hinge. The 0.5 is the launch flag --safe-hinge-weight. The yaml default 0 would make _safe_hinge return 0.

  • Keep windows whose label peak is below 0.25 (loss.safe_hinge_threshold) and whose sample mask is true.
  • safe_hinge_margin is 0 in the yaml, so the cap is 0.25.
  • The term is the mean of relu(predicted peak − 0.25) on those windows. An empty set returns 0.

This compares the predicted probability peak with 0.25 on unmasked SAFE windows. A high value means that peak climbed to 0.25 or above. Windows whose label peak is 0.25 or higher stay out.

Close-head loss

1.0 ×

Called L_close. Function TeacherLoss._close, which calls soft_bce on probabilities. The 1.0 is the launch flag --close-weight. The yaml default 0 skips the term and skips loading the closing maps.

  • Hhat_close is the sigmoid of a 1×1 convolution on Z_t, shape [B, 5, 5].
  • The target h_close and the multiplier close_mask are the approaching map and the occupancy map at the anchor plus 30 frames, the first entry of horizons_frames.
  • Inside _close, the positive threshold is 0.5 and the positive weight is 2.0, both hardcoded. A cell with h_close above 0.5 gets ×2, then the weight is multiplied by close_mask and by the sample mask.
  • The term is the same weighted mean as soft_bce. Cells with close_mask 0 drop out of the sum.

This compares the side head on Z_t with the auxiliary approaching map. A high value means that head missed, with extra weight where the approaching target is above 0.5. Students do not use this head.

False-positive loss

0.10 ×

Called L_FP. Function false_positive_penalty. The 0.10 weight is yaml loss.false_positive_weight.

  • Keep cells whose h_1s is below 0.05 (loss.safe_cell_threshold) and whose sample mask is true.
  • Mean of relu(Hhat_1s − 0.10) squared. The 0.10 margin is yaml loss.false_positive_margin.
  • An empty keep-mask returns 0.

This compares an empty cell with a free margin of 0.10 on the probability map. A high value means the probability rose above that margin.

Direction loss

0.05 ×

Called L_dir. Function direction_alignment_loss. The 0.05 is yaml loss.direction_weight. Temperature 0.08 is yaml loss.direction_temperature.

  • Row weights are yaml adapter.row_weights 1, 1, 1, 1, 1. The code divides by their mean, which leaves them at 1, then multiplies the probability map by those weights.
  • Left score = 0.08 × the log of the sum of exp(row-weighted cell / 0.08) over columns 0 and 1. Those columns are yaml evaluation.left_cols.
  • Center uses column 2 (evaluation.center_cols). Right uses columns 3 and 4 (evaluation.right_cols).
  • Smooth-L1 between the prediction’s three scores and the label’s three scores.
  • Only samples whose largest label side score is at least 0.25 (loss.direction_threat_threshold) and whose sample mask is true. An empty set returns 0.

This compares the left, center, and right soft scores of Hhat_1s with the same scores of h_1s. A high value means the side profile disagrees. The gate is the side-score max, at this teacher’s 0.25 line.

Background loss

0.02 ×

Called L_bg. Inside TeacherLoss the value is 0. The cosine that is trained is background_consistency_loss, added by PhaseTrainer._bg_pair_tensor. The 0.02 is yaml loss.background_consistency_weight. This cosine is separate from the pair-difference shrink.

  • Z_t is [B, 32, 5, 5]. The term is the mean of (1 − cosine) of the 32-d vectors, over the 5×5 cells of pairs that found a mate.
  • The mate is a detached earlier Z_t in PairBuffer, keyed by background pair id and anchor, and it must be a different clip.
  • The lookup runs only where bg_pair_valid is true. That flag is background_pair_valid: different clip, same outcome, same scenario group, same background pair id, at least one horizon in range, and every in-range horizon heatmap agrees with maximum cell absolute difference at most 0.001.
  • The trainer adds 0.02 times this cosine on the clean forward, after the counterfactual term. No mate in the buffer leaves the term at 0. The shrunk-token forward does not call _bg_pair_tensor.

This compares the current Z_t with a detached mate from an earlier step. A high value means those cell directions differ.

Pair-CF copy of the TeacherLoss sum

beta × ramp

Added in PhaseTrainer._forward_loss. Shrink function apply_pair_counterfactual_shrink. Beta function calibrate_beta_pair_counterfactual. The subspace file is reports/pair_background_counterfactual/subspace/learned_k16.npz, the yaml default and the path the launch script passes. pair_cf_lambda is 1.0 in the yaml.

  • The add runs when background regularization is on, the pair-counterfactual flag is on, U is loaded, the ramp is above 0, beta is above 0, and _pair_cf_pair_pick is true.
  • The pick requires bg_reg_paired, a non-empty background_pair_id, and a first SHA-256 byte below 128 for the string epoch|background_pair_id[0]|pair_cf_aux. One decision covers the batch.
  • Ramp, from pair_cf_ramp_strength: epoch 0 is 0, epoch 1 is 0.25, epoch 2 is 0.50, epoch 3 is 0.75, and epoch 4 onward is 1.0.
  • Shrunk tokens replace batch["tokens"]. Labels, including h_1s and amb_1s, stay as they are. The copied value is TeacherLoss.total on that batch, so it includes the cell, blob, STOP, SAFE, close, false-positive, and direction terms, and its L_bg is 0.
  • The weight is beta × ramp. When beta is still unset, epoch 1 (pair_cf_calibrate_epoch) sets it from up to 100 hash-accepted pair batches (pair_cf_calibrate_batches). The value is 0.10 / median(g_cf / (g_clean + 1e-8)). At ramp 1 that targets about 10% of the clean adapter-and-decoder gradient. A resumed checkpoint keeps a stored beta. While beta is unset, this add stays off.

This repeats the occupancy sum after the pair-difference subspace is shrunk in the Giant tokens. A high value means the 1 second map is hard to explain from the channels that remain.

Student M1

docs/student_m1_model.md. M1 does not use the parent’s BCE, the ×8 appear weight, the blob term, the STOP and SAFE hinges, or the PCA shrink. Decoder logits are unused. Spatial weights are built and then set uniformly to 1 in this run, because the energy, appear, and stop boosts are all 0.

Total = latent loss + task loss + 0.01 × decoder-anchor loss

=
1 × feature loss Latent loss = 1 × feature loss + 0.2 × cosine loss + 0.5 × masked-predictor loss + 0.2 × spatial-Gram loss Compares whitened student F with detached whitened parent F_dec. A high value means the amplitudes disagree.
+
0.2 × cosine loss Compares each cell’s 128-direction with the parent’s direction. A high value means a cell points away. Scale is ignored.
+
0.5 × masked-predictor loss Compares a fill-in of half-masked F_ctx with the whitened parent map. A high value means the hidden cells were not recovered.
+
0.2 × spatial-Gram loss Compares which of the 256 cells light up together. A high value means that pattern differs from the parent.
+
0.8 × heatmap loss Task loss = 0.8 × heatmap loss + 0.6 × STOP-floor loss + 0.4 × distillation loss Compares Hhat_1s with the 1 second label using Smooth-L1. A high value means the heatmap is wrong, especially on occupied cells.
+
0.6 × STOP-floor loss If the ground truth says STOP, penalize how far the peak sits below 0.70. A high value means a true STOP window stayed too low.

0.4 × distillation loss Compares the student map with H_teacher when the parent’s class already matches the label. A high value means those maps differ.
+

Whitening, shared by the feature term and the masked term, uses the cached per-channel mean and scale of parent F_dec, shaped [128, 1, 1]. Whitened value = (feature − mean) / (scale + 10−6).

Feature loss, whitened absolute error

1 ×

Called L_feat. Coefficient 1 inside the latent loss. Parent features are detached.

  • At each cell, average the absolute difference over the 128 whitened channels.
  • Then average over space. In this run the spatial weight is 1.

This compares the whitened student map with the whitened parent map. A high value means the amplitudes disagree, without letting a few high-variance channels dominate.

Cosine loss, per cell

0.2 ×

Called L_cos. Unwhitened features.

  • At each spatial site, normalize the student’s 128-vector and the parent’s 128-vector to unit length.
  • Cell cost = 1 − their dot product.
  • The term is the weighted mean of those costs.

This compares the direction of each 128-vector with the parent’s direction. A high value means a cell points away from the parent. Scale is ignored.

Masked-predictor loss

0.5 ×

Called L_mgd.

  • Mask each of the 16×16 cells with probability 0.5.
  • Predict a completed map from the masked F_ctx.
  • Same whitened weighted absolute error as the feature loss. The target is the whitened parent map.

This compares the predictor’s fill-in with the parent map. A high value means a half-hidden F_ctx was not completed. The heatmap decoder does not use this predictor.

Spatial-Gram loss

0.2 ×

Called L_rel. The student note says this Gram is not the parent’s pair-difference PCA.

  • Flatten 16×16 into 256 locations.
  • L2-normalize each location across the 128 channels.
  • Form the 256×256 Gram of pairwise dots between locations. The note writes that matrix as P transpose times P.
  • Mean squared error between the student Gram and the parent Gram.

This compares which cells light up together. A high value means that co-activation pattern differs from the parent.

Heatmap loss, occupied Smooth-L1

0.8 ×

Called L_h. Inside the task loss. Smooth-L1 beta = 0.05. Occupied means the label is at least 0.25.

  • Let o be 1 on occupied cells and 0 otherwise.
  • Cell weight = 0.12 × (1 − o) + 4 × o × (0.5 + the label clipped into 0 to 1).
  • The term is the mean of cell weight × Smooth-L1 between the prediction and the label.

This compares Hhat_1s with the 1 second label. A high value means the heatmap is wrong. Empty cells get a small pull. Occupied cells, especially high STOP values, get a much larger pull. It is Smooth-L1, not BCE.

STOP-floor loss

0.6 ×

Called L_floor. Only samples whose label peak is at least 0.60. If the batch has no STOP sample, the term is 0.

  • If the ground truth says STOP, penalize how far the predicted peak sits below 0.70.
  • Average that penalty over the ground-truth STOP samples.

A high value means a true STOP window stayed under 0.70. There is no matching SAFE hinge. The parent’s STOP hinge used 0.65. This floor uses 0.70.

Distillation loss

0.4 ×

Called L_kd. Selective parent heatmap.

  • Keep a sample only when the parent’s warning class equals the label’s class.
  • Sum of (sample weight × L1 distance between the student map and H_teacher), divided by (the sum of sample weights × 25).

This compares the student heatmap with H_teacher on windows where the parent’s class is already the right class. A high value means those maps differ. A parent false STOP is left out.

Decoder-anchor loss

0.01 ×

Called L_dec_reg. The anchor is the Pair-CF decoder initialization.

  • For each parameter tensor, take the mean of (current value − initial value) squared.
  • Then take the mean of those tensor means.

This compares decoder weights with the copied initialization. A high value means the weights walked away. The tiny steps at epochs 9 and 10 still fit under it. The note says this is a per-tensor mean, not one global root-mean-square.

At official epoch 10 the note’s training means are about feature 0.462, cosine 0.173, masked predictor 0.463, spatial Gram 0.053, heatmap 0.030, STOP floor 0.016, distillation 0.028, and decoder anchor about 10−8. The note describes the weighted latent sum as about 0.75 and the total as about 0.78, with the task terms a small add-on. There is no EMA mix and no pair-CF PCA in this loss.

What the student is built to match

The student is trained against the one-second parent. Cached targets are that parent’s F_dec and H_teacher, plus the group-mean 1 s label. The decoder weights start as that parent’s decoder. The latent loss is most of the training signal at epoch 10. The STOP floor, the Smooth-L1, and the selective heatmap term are the smaller task add-on.

CollisionTeacher3 remains the four-horizon model in the root notes, with its own mean-and-last adapter, its own copy-residual heads, its own weighted squared-error loss, and its own 0.70 / 0.42 warning rule. Its phase-B LoRA run is part of that teacher. It is not the parent checkpoint the student copies.

Street-video files under the student_lat name are the same architecture family and a different weight file: epoch 37, not checkpoint_epoch_10.pt.
